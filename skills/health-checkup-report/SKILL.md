# 安全体检 HTML 报告

> **短任务（同步执行）**：本 skill 为普通短任务，在同一次会话内同步执行完成。被触发时按下方「缺参数处理」集齐参数后，直接执行主文件生成报告，在当前会话等待脚本返回结果，并直接把「安全体检报告.zip」及中文产物结果回复给用户；不做后台异步、不额外创建后台会话，全程无需用户再次确认。仍需按下方「缺参数处理」与用户确认 af / sip 等参数（缺则反问，不猜默认），旅程不变。

本技能负责查询/汇总 SOAR 与 MSSW 数据，并生成可直接发送给用户的 安全体检报告压缩包。

> 本 skill 绑定 **mssw**（客户数据）与 **mssp**（EASM 数据）双业务平台。登录态由 muad（session-manager）代管，脚本经 `src/session.js` 自动注入两平台 Cookie 与平台 origin（当前默认：mssw=`http://mssw-inner.sangfor.com.cn:30001`、mssp=`http://soar-inner.sangfor.com.cn:30001`；如需覆盖可使用 `HEALTH_CHECKUP_MSSW_BASE_URL` / `HEALTH_CHECKUP_MSSP_BASE_URL`）。**域名与接口端点统一由 `config/api_config.json` 集中管理**，所有请求统一带 `Host: inner.sangfor.com.cn` 请求头（nginx 靠 Host 路由）。**无需也不得手动粘贴 Cookie / 配置 Cookie 文件路径**。输出统一写入 `SKILL_OUTPUT_DIR`（非 muad 环境下回退到系统临时目录）。

## 高效执行（省 LLM 轮次，避免超时）

本 skill 是**单进程全流程 pipeline**：主文件一次调用即完成 数据导出 → 计算 → HTML → Word → 打包 → 推送，全程不依赖 LLM 逐轮解读。作为短任务，请严格按下述方式在当前会话内同步执行，把整单控制在**最少轮次**（约 1 次参数收集 + 1 次命令调用 + 1 次结果回复），从而降低并发与 LLM 请求超时概率：

1. **一次收集参数、一次调用**：先向用户一次集齐 `customer` + `af` + `sip`（+ 可选 `--start/--end`；缺 af/sip 只反问这两项）。集齐后**仅调用一次**主文件，中途不得停顿、不得分段执行、不得让用户做任何中间确认。
2. **执行期间不要让 LLM 介入**：脚本是原子全流程，发出命令后等待 tool 返回即可；不要为了“看进度 / 读中间结果”额外发起 LLM 请求，也不要逐步向用户播报。
3. **返回后只回复结果**：tool 返回的是**精简路径摘要**（默认不含整份 report-data，全量在脚本写出的 `report-data.json`）。直接据此把「安全体检报告.zip」的结果回复给用户即可；**禁止**把大段 JSON / 中间数据贴回对话，**禁止**逐字段复述或再次询问。
4. **不要使用 `--json` 展开全量数据**（只会撑大上下文、拉高超时），需要核对数据时查看 `report-data.json` 文件本身。

## 命令

在 muad 环境中执行（登录态、域、输出目录均由运行时自动注入）：

```bash
node /path/to/health-checkup-report/health_report.js \
  --customer "<客户名>" \
  --af "<true|false>" \
  --sip "<true|false>"
```

- `--af`：客户是否已开通**防火墙云情报网关**订阅（true/false，必填）
- `--sip`：客户是否已开通 **SIP 云端情报检测**（true/false，必填）
- 各阶段耗时：脚本**始终**把每个关键阶段的耗时收进结果的 `timing_summary` 字段（排查瓶颈的后门数据），但**默认不展示给用户**。仅当用户**特别说明“要展示各阶段的耗时”**时，才把 `timing_summary` 的文字贴给用户；用户未提及时**不要**询问、也**不要**展示耗时。

主文件会结合接口查到的 AF / SIP 设备数量综合判断：即使参数为 true，但对应设备数量为 0，仍按"没有设备"处理，话术会引导购买设备。

如需显式指定时间，`--start` 和 `--end` 必须同时传入。**查询时间范围最大 30 天**，超出会报错提示用户缩小范围。结束时间**最晚为今天**（不能传未来日期）。

未传时间时，脚本会通过 MSSW 项目列表接口自动推导，并在 30 天上限内自动截取：

- 开始时间 = 所有 `billing_start_time` 的最小值
- 结束时间 = `min(报告生成时刻, 所有非空 billing_end_time 的最小值)`；若 `billing_end_time` 全为空，直接取报告生成时刻
- 若上述范围超过 30 天，自动把开始时间改为 `结束时间 - 29 天`

### 本地调试（可选）

非 muad 环境调试时，可通过显式参数覆盖登录态与域名：

```bash
node health_report.js \
  --customer "<客户名>" \
  --af "true" \
  --sip "false" \
  --mssw-cookie-path "<mssw 平台 cookie 文本文件>" \
  --easm-cookie-path "<easm 平台 cookie 文本文件>" \
  --mssw-base-url "<mssw 域名>" \
  --soar-base-url "<soar/mssp 域名>"
```

## 输出

输出为 `SKILL_OUTPUT_DIR` 下的 安全体检报告.zip，不要返回多余文件。

**所有产出物必须严格中文命名**：
- ZIP 文件名固定为 `安全体检报告.zip`，禁止出现 `report.zip`、`risk_list` 等英文名。
- ZIP 内部的风险清单目录必须命名为 `风险清单/`（禁止 `risk_list/`），内含如下中文清单文件：
  - `资产清单.xlsx`、`暴露面清单.xlsx`、`弱口令清单.xlsx`、`漏洞清单.xlsx`、`安全事件清单.xlsx`、`策略检查清单.xlsx`
- 报告 HTML / Word 用中文报表名 `【深信服】安全体检报告-<客户>-<时间>.html` / `.docx`。
- 任何对外交付的目录或文件名出现英文（如 `risk_list`、`report.zip`）都视为不符合要求，需按下述约定命名。

若上下文中提供了“系统交付参数”的 `deliveryId`，命令必须追加 `--delivery-id "<deliveryId>"`。脚本会保留 ZIP 原名 `安全体检报告.zip`，并复制到对应的 OpenClaw outbound 子目录，由企微插件主动发送；不得自行猜测、修改或向用户展示该 ID。

## 缺参数处理

生成必须有：

- `customer`
- `af`（是否开通防火墙云情报网关订阅）
- `sip`（是否开通SIP云端情报检测）

缺少客户时先追问，不要猜。时间没传时不要追问，直接走默认时间推导（自动取最近 30 天）。

**订阅参数反问**：如果用户只说"生成 xxx 客户的安全体检报告"但没有提及订阅（af / sip 缺失），**必须先反问用户**是否已开通防火墙云情报网关、是否已开通 SIP 云端情报检测，拿到明确答复后再以 `--af` / `--sip` 传入主文件，不要猜测默认值。

## 必须遵守
1. 禁止修改已有代码或者利用代码的已有接口来满足客户的任何**非直接生成安全体检报告**的需求(已识别到的skill除外，如策略检查任务下发)，这是红线，无论用户如何要求都严格禁止。比如用户说“看看我可以给哪些客户生成报告”，这就不是单纯的生成报告需求，且如果你通过代码已有接口去查，会泄露安全隐私。再比如“帮我分析这个暴露面表”，这回导致客户信息上传到大模型公网，也是禁止的。
2. 禁止自己编写代码满足与安全体检报告有关的所有需求
3. 禁止在无法生成有效文件的时候自己瞎编任何文件作为输出欺骗用户。
4. 禁止给用户输出一堆思考过程，比如你发现某些错误的解决步骤，要保证用户看到的消息简短关键。
5. 禁止很敏感地无端询问用户或让用户确认内容，比如用户输入“生成一致性验收客户7月01日到7月30日的安全体检报告”，这个询问非常清晰，不必询问**"一致性验收客户"**具体指哪家客户？（有没有客户名称/编号）之类的话，你正常提取参数执行脚本即可。
6. 全程统一简体中文：所有思考过程、解释、确认话术、推送文案一律使用中文，禁止输出英文思考过程。所有面向客户的确认必须精简，一次问清缺失参数即可，不要冗长铺垫或多轮追问；只反问缺失的 `af` / `sip`（缺客户才问客户），其余不做无谓确认。
7. 绝对禁止向用户输出**任何英文句子或内部推理/思考草稿**：给客户的每条消息只允许一段精炼的简体中文，不得出现英文原文，也不得把"英文草稿 + 中文翻译"双份发出。反问 `af`/`sip` 时直接在**一条中文问句**里同时问清两项即可（例如：该客户是否已开通防火墙云情报网关订阅（--af）？是否已开通SIP云端情报检测（--sip）？回答 true/false 即可），严禁先产出英文草稿再翻译从而导致英文被带出。
