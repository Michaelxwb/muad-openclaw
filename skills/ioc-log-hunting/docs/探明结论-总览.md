# 全网日志恶意内容摸排 Skill —— 探明结论归档

> 阶段性存档：2026-09-03。用于给使用者做"某客户 + 恶意内容(URL/IP/Hash) → 近3天有哪些客户主机曾与该恶意内容交互"的深度风险提醒素材。
> 本 skill 由用户与 agent 逐表验证推进，最新进度：DNS(20) 已跑通并锁定逻辑；TCP(100)、遥测(28) 待验证。

---

## 一、业务目标与输入/输出

**输入（使用者每次明确指定）：**
1. 客户（测试样本 = 绝味食品，company_id=`97988530`）
2. 恶意内容类型 + 值：
   - 恶意 **URL / 域名** → 查 **DNS(20)** 表
   - 恶意 **IP** → 查 **TCP(100)** 表
   - 恶意 **Hash** → 查含文件字段的表（26/28 系，需继续探，**不与 DNS/IP 混查**）

**输出：**
- 近 **3 天**内，该客户下与恶意内容**有过交互**的**客户主机 IP(srcIp) 去重清单**
- 每台主机列出：命中条数 + 最早/最晚交互时间
- 附关键日志证据，供使用者对客户做更深度的风险提醒

> 判定"是否真恶意"由使用者侧情报负责，本 skill 只做客观检索与关联。

---

## 二、关键约定（使用者强约束，硬编码进 skill）

1. 输入只可能是**真恶意**内容（不会有"非恶意"的误标需要本 skill 二次判断）。
2. **时间窗固定近 3 天**（不是 7 天）。
3. 恶意 **URL → DNS**；恶意 **IP → TCP**；恶意 **Hash → 文件日志表**。表与内容类型严格对应。
4. DNS 只查 **`queries`** 字段，用**精准匹配**（不经 LIKE 模糊）。
5. srcIp **不做内网过滤**，全量取，**只做去重**。
6. 若命中日志总数 **> 10000 条**：提示使用者"访问量过大，该域名可能并非真恶意"，然后**翻取 1 万条**做 srcIp 去重展示（不全量翻）。
7. 每次检索**只查使用者指定的单一客户**，不跑所有客户。

## 三、平台与登录态（复用既有管道）

- 接口公网域名：`https://soar.sangfor.com.cn`；本 skill 实测走**内网** origin 可达：
  `http://soar-inner.sangfor.com.cn:30001` + `Host: inner.sangfor.com.cn`（nginx 靠 Host 路由）。
- 登录态：由 muad 的 **session-manager** 代管，脚本经 `session-manager get-state --skill-name <SKILL_NAME>` 取 mssp 平台 cookie，**绝不手动粘贴 Cookie / 不打凭据到日志**。
- 参考可复用模块：`skills/monitor-mssp-events/scripts/shared.py`
  - `get_cookie()`、`build_headers()`（会带固定 `X-CSRFToken` + `timezone +08:00`）、`http_json()`
  - sniff：本 skill 应自带一份 copy 或 import（skill 间目录隔离，建议自带，勿依赖他 skill 路径）。
- 请求头模拟浏览器；`referer` = origin + `/index.html`。
